## Summary of changes

All PoCo facets are replaced. The diamond proxy, the core diamond facets
(`DiamondCutFacet`, `DiamondLoupeFacet`, `OwnershipFacet`), the registries and the
already deployed `IexecLibOrders_v5` library are left untouched.

No function selector is lost: the `receive` (`0x00000000`) and `fallback`
(`0xffffffff`) selectors move from `IexecEscrowTokenFacet` to
`IexecEscrowFacet`.

### Breaking changes

-   Remove native mode contracts: `IexecEscrowNativeFacet`, `IexecEscrowNative`,
    `IexecInterfaceNative`. Only the token mode remains. (#343)
-   Remove the `token` suffix throughout: `IexecEscrowTokenFacet` becomes
    `IexecEscrowFacet`, `IexecEscrowToken` becomes `IexecEscrow`, and
    `IexecInterfaceToken.sol` becomes `IexecInterface.sol`. (#356)
-   Remove `setName` from `Registry` and `RegistryEntry`, together with reverse
    registration support. (#344)
-   Remove Bellecour support. (#341)
-   Merge `IexecPoco1Errors` into `IexecPoco1`. The `IexecPoco1Errors` interface
    and its ABI are gone; `IncompatibleDatasetOrder` is now declared on
    `IexecPoco1`.

### Internal changes

-   Merge `IexecERC20Base` into the escrow facet. (#345)
-   Convert abstract contracts to libs:
    - `IexecEscrow` => `EscrowLib` and `StakedRlcLib`
    - `SignatureVerifier` => `CommonLib`,
-   `FacetBase.owner()` now reads the diamond storage through
    `LibDiamond.contractOwner()` instead of an external `IERC5313` call.

### Not shipped by this upgrade

The `Registry` and `RegistryEntry` changes (`setName` removal, migration shim
removal) are **not** delivered here. `AppRegistry`, `DatasetRegistry` and
`WorkerpoolRegistry` are standalone contracts, not diamond facets, and the
`App` / `Dataset` / `Workerpool` masters are fixed at registry construction. A
`diamondCut` cannot reach them.

Those changes take effect only on a fresh chain deployment, or through a
separate registry migration that deploys new registries chained to the current
ones via `initialize(_previous)` and repoints the proxy with `changeRegistries`.
That migration changes the registry addresses and is out of scope for v7.0.0.
